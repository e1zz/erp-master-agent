# Walmart Global Marketplace Webhooks & Event Notifications

## Use When

- Setting up real-time event listeners for Walmart Marketplace (e.g., new orders, inventory changes).
- Implementing webhook signature validation (HMAC-SHA256).
- Ensuring durable, idempotent processing of Walmart events.

## Subscribing to Webhooks

Unlike MercadoLibre where webhooks are configured globally per App, Walmart subscriptions are managed via the Developer Portal or via the API (`POST /v3/settings/subscriptions`).

You must configure an endpoint URL that can receive `POST` requests and respond with a `200 OK` status code quickly.

### Managing Subscriptions via API

| Action | Endpoint | Description |
|---|---|---|
| **List Subscriptions** | `GET /v3/settings/subscriptions` | Returns all active webhook subscriptions |
| **Create Subscription** | `POST /v3/settings/subscriptions` | Create a new subscription for a specific event type |
| **Delete Subscription**| `DELETE /v3/settings/subscriptions/{subscriptionId}` | Removes a subscription |

## Critical Events

| Event Type | Description |
|---|---|
| `PO_CREATED` | A new purchase order has been created. (Triggers your acknowledgment worker). |
| `PO_UPDATED` | An order's status has changed (e.g., Walmart canceled it, or WFS shipped it). |
| `RETURN_CREATED` | A new return request was initiated. |
| `RETURN_UPDATED` | A return's status changed (e.g., delivered, refunded). |
| `ITEM_PUBLISHED` | An item's status changed to published. |
| `ITEM_UNPUBLISHED` | An item was unpublished. |
| `INVENTORY_UPDATE` | Inventory levels were updated. |
| `FEED_STATUS` | A bulk feed (item setup, inventory, etc.) finished processing. |

## Webhook Signature Verification (CRITICAL)

Walmart secures webhooks by signing the payload. **You must verify this signature before processing the event.**

Walmart does *not* sign requests with an RSA key anymore; they use HMAC-SHA256 based on a shared secret (Client Secret).

### 1. Extract Headers

Walmart sends the following crucial headers with every webhook:
- `WM_SEC.AUTH_SIGNATURE`: The HMAC-SHA256 signature generated by Walmart.
- `WM_CONSUMER.INTIMESTAMP`: An epoch timestamp in milliseconds when the event was fired.
- `WM_SVC.NAME`: `Walmart Marketplace`

### 2. Verification Logic

To verify, you must reconstruct the payload string, hash it using your Client Secret, and compare it to the signature in the header.

**Payload Construction:**
The exact string to sign varies slightly depending on the documentation version, but generally, it is the exact raw JSON body combined with the timestamp.
*Standard Format:* `[timestamp]\n[raw_json_body]\n`

**PHP Example:**

```php
public function verifyWalmartWebhook(Request $request, string $clientSecret): bool
{
    $signatureHeader = $request->header('WM_SEC.AUTH_SIGNATURE');
    $timestampHeader = $request->header('WM_CONSUMER.INTIMESTAMP');
    $rawBody = $request->getContent();

    if (!$signatureHeader || !$timestampHeader) {
        return false;
    }

    // Protect against replay attacks (e.g., reject if older than 5 minutes)
    $timestampMs = (int) $timestampHeader;
    if ((microtime(true) * 1000) - $timestampMs > 300000) {
        return false;
    }

    // Construct the signing string.
    // NOTE: Always consult the latest Walmart docs for the exact string format.
    // It is typically the Timestamp + newline + Raw Body
    $stringToSign = $timestampHeader . "\n" . $rawBody . "\n";

    // Hash with HMAC-SHA256
    $computedHash = base64_encode(hash_hmac('sha256', $stringToSign, $clientSecret, true));

    // Constant-time comparison
    return hash_equals($signatureHeader, $computedHash);
}
```

## Payload Structure

Webhooks wrap their data inside a `payload` object and include an `eventId` for deduplication.

**Example `PO_CREATED` Payload:**
```json
{
  "source": "WALMART_MARKETPLACE",
  "eventType": "PO_CREATED",
  "eventId": "e89b-12d3-a456-426614174000",
  "eventTime": "2024-01-01T12:00:00.000Z",
  "payload": {
    "purchaseOrderId": "111222333444",
    "customerOrderId": "999888777666",
    "orderDate": "2024-01-01T11:59:00.000Z",
    "shippingInfo": {
      "methodCode": "Standard"
    }
  }
}
```

## Idempotency and Durable Receipts

1.  **Acknowledge Immediately:** Your endpoint must return `200 OK` as fast as possible.
2.  **Queue the Work:** Push the raw webhook payload to a queue (e.g., Redis/RabbitMQ) for asynchronous processing.
3.  **Deduplicate:** Use the `eventId` (or `purchaseOrderId`) to ensure you do not process the same webhook twice. Walmart guarantees "at-least-once" delivery, meaning duplicates *will* happen.
